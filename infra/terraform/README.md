# Searchlyst infra (Terraform)

Provisions all GCP infrastructure for one Searchlyst environment (`staging` or `prod`):

- Required APIs
- VPC peering for Cloud SQL private IP
- Cloud SQL for PostgreSQL 16 (with daily backups + 7-day PITR + failure alert)
- Artifact Registry repo
- Static external IP, Compute Engine VM (Ubuntu 22.04)
- Firewall rules (HTTP from anywhere, SSH via IAP)
- Two service accounts: `vm-runtime-<env>` (attached to the VM) and `gha-deployer-<env>` (used by GitHub Actions, JSON key emitted as a sensitive output)

The on-VM setup (Docker, nginx) and TLS install are still bash scripts in `infra/gcp/` — Terraform only owns the cloud resources.

## One-time setup

1. Install [Terraform 1.6+](https://developer.hashicorp.com/terraform/install) and the [gcloud CLI](https://cloud.google.com/sdk/docs/install).
2. Sign in: `gcloud auth login` and `gcloud auth application-default login`.
3. Create the GCS bucket that holds Terraform state (one-time per project):

   ```bash
   export GCP_PROJECT_ID=your-project-id
   bash infra/terraform/bootstrap-state-bucket.sh
   ```

4. Edit [envs/staging.tfvars](envs/staging.tfvars) and set `project_id` and `alert_email`.

## Provisioning staging

From `infra/terraform/`:

```bash
export GCP_PROJECT_ID=your-project-id

ENV=staging make init     # init + select workspace
ENV=staging make plan     # preview
ENV=staging make apply    # ~12 min the first time (Cloud SQL is the slow part)
ENV=staging make secrets  # prints values to paste into GitHub secrets
```

## Adding a prod environment later

1. Copy `envs/staging.tfvars` to `envs/prod.tfvars`, change `project_id`, `environment = "prod"`, bump `vm_machine_type` and `db_tier`.
2. (Recommended) use a **separate GCP project** for prod for blast-radius isolation.
3. Run `bash infra/terraform/bootstrap-state-bucket.sh` against the prod project once to create its state bucket.
4. Then:

   ```bash
   export GCP_PROJECT_ID=your-prod-project-id
   ENV=prod make init
   ENV=prod make plan
   ENV=prod make apply
   ```

The same modules and the same VM startup script are used — no duplicated code.

## Common operations

| Task | Command |
|---|---|
| Show all outputs | `ENV=staging make outputs` |
| Print secrets to copy into GitHub | `ENV=staging make secrets` |
| Re-render only (e.g. after changing a variable) | `ENV=staging make plan` |
| Format files | `make fmt` |
| Validate config | `make validate` |
| Tear it all down | `ENV=staging make destroy` (set `deletion_protection=true` in `modules/database/main.tf` for prod) |

## Where things live

```
infra/
  terraform/
    backend.tf, providers.tf, variables.tf, main.tf, outputs.tf
    Makefile, bootstrap-state-bucket.sh, README.md
    envs/
      staging.tfvars      # committed (no secrets)
      prod.tfvars         # add later
    modules/
      apis/               # google_project_service
      network/            # VPC peering for Cloud SQL
      database/           # Cloud SQL + backups + PITR + monitoring alert
      registry/           # Artifact Registry
      compute/            # static IP, VM, firewall, 2 service accounts, GHA key
  gcp/
    vm-startup.sh         # baked into the VM by Terraform
    setup-tls.sh          # run on the VM later, after pointing a domain at it
```

## Notes / gotchas

- The GHA service-account JSON key is stored in the Terraform state file. Keep the GCS state bucket private (the bootstrap script enables uniform access + public-access prevention) and rotate the key by running `terraform apply -replace=module.compute.google_service_account_key.gha`.
- The Cloud SQL DB password is also generated by Terraform (`random_password`) and lives in state. Same protection applies. Print it with `terraform output -raw database_url`.
- `deletion_protection = false` on the Cloud SQL instance for staging convenience. **Flip it to `true` for prod** in `modules/database/main.tf` before applying prod.
- `metadata_startup_script` is in `lifecycle { ignore_changes = [...] }` so editing `vm-startup.sh` doesn't recreate the VM. To re-run the script on the existing VM:

  ```bash
  gcloud compute ssh --tunnel-through-iap --zone=asia-south1-a searchlyst-staging-vm \
    --command='sudo google_metadata_script_runner startup'
  ```
